# Plan: Migrate ESP32 Gateway RTC from DS3231 (21/22) to DS1307 (12/13)

## Goal
Replace the existing DS3231 hardware RTC path with the MKE-M09 DS1307 module on GPIO 12 (SDA) and 13 (SCL), retain the strict fallback hierarchy DS1307 → ESP-IDF/NTP → invalid (safe-OFF), add a backend→gateway authoritative time-set path, and ensure offline schedule execution remains deterministic from RTC.

## Decision
Full migration to DS1307 on GPIO 12/13. Retire DS3231 on pins 21/22. Do not keep two parallel RTC instances.

## Firmware Changes

### 1. Pin contract
- Update `aeroponics-firmware/include/config.h`
  - `RTC_SDA_PIN = 12`
  - `RTC_SCL_PIN = 13`

### 2. RtcManager DS1307 adaptation
- Update `aeroponics-firmware/include/rtc_manager.h`
  - Replace `RTC_DS3231` with `RTC_DS1307`.
  - Rename lost-power semantics to `isOscillatorStopped()` / `hasPowerLoss()` using DS1307-compatible detection.
  - Keep public interface: `begin()`, `syncFromNtp()`, `adjustTime(const DateTime&)`, `getTime()`, `isNightMode()`.
- Update `aeroponics-firmware/src/rtc_manager.cpp`
  - Use `rtc_.begin()` on I2C pins already started by `Wire.begin(RTC_SDA_PIN, RTC_SCL_PIN)`.
  - Detect DS1307 power loss via squarewave/CH bit unavailable path; RTClib exposes `lostPower()` for DS1307 as `seconds == 0` in most builds. Treat that as untrusted until backend/NTP set.
  - Keep fallback hierarchy exactly:
    1. trusted DS1307
    2. ESP-IDF system time/NTP
    3. invalid → safe-OFF in scheduler

### 3. Backend authoritative time downlink
- Add new inbound MQTT command type for gateway clock control.
  - Extend `MqttInboundCommandType` with `GATEWAY_CLOCK` in `aeroponics-firmware/include/mqtt_client.h`.
  - Parse topic `config/clock` or existing gateway config topic family.
  - Enqueue command to `_applyInboundCommand`.
- Apply handler:
  - Validate JSON: `{ command_id, unix_time_utc, tz_offset_s, local_time }`
  - Convert provided UTC epoch to `DateTime` and call `g_rtc_manager.adjustTime(dt)`.
  - Set trusted state true after apply.
  - Ack via gateway command ack topic.
- Add NVS write-through:
  - Persist last backend-provided timestamp and tz offset in NVS so power-cycle retains an older but still plausible reference until next Wi-Fi/NTP.

### 4. Periodic NTP re-sync / drift compensation
- Current behavior: single NTP sync on first Wi-Fi connect.
- Add periodic re-sync cadence every 6 hours when Wi-Fi is connected.
- On successful NTP, correct DS1307 drift even if RTC already trusted.
- On successful backend `GATEWAY_CLOCK`, mark backend source trusted and suppress NTP override for that interval.

### 5. MQTT heartbeat telemetry improvements
- Keep `ntp_synced` and `rtc_valid` as already used by backend `device_status`.
- Add optional `time_source` enum string: `DS1307_RTC | SYSTEM_NTP | BACKEND | INVALID`.
- Add `last_sync_unix_time_utc` so backend can see recency of sync.

### 6. Time-jump / monotonicity safety
- DS1307 has no sub-second monotonic counter; scheduler uses 1-second `stepGroupSchedule()` tick from `millis()`-driven main loop.
- After RTC adjust, do not reconstruct phase state from RTC wall clock; only advance schedule ticks. This preserves deterministic phasing and avoids back-jump issues.
- If RTC becomes invalid at runtime, `GroupScheduler::validateRuntimeClock` already forces safe-OFF; no change needed.

### 7. ATmega8 node interaction
- `atmega8_node_main.cpp` has local autonomous schedule logic. It does not own shared `IClock` with gateway.
- Do not change node firmware scope unless requested; gateway-side fallback only affects node pump commands, not node clock.

## Backend Changes

### 1. Gateway config endpoint or MQTT topic
- Prefer MQTT topic `aeroponics/gateway/{device_id}/config/clock` for time setting.
- Backend service to publish `{ command_id, unix_time_utc, tz_offset_s, local_time }` to gateway.
- Backend already consumes heartbeat `ntp_synced` / `rtc_valid` into `device_status`; no schema change needed.

### 2. Clock sync service
- Add scheduled backend job to push time to gateways when time delta > threshold or nightly.
- Use timezone-aware Asia/Ho_Chi_Minh epoch conversion to ICT local time for payload consistency.

### 3. Observability
- Backend UI/device status already shows `ntpSynced`, `rtcValid`, `lastSeenAt`.
- Add optional `timeSource` and `lastSyncUnixTimeUtc` display fields in device status DTO if firmware adds them.

## Wiring & Hardware Checklist
- DS1307 module VCC 5V or 3.3V depending on module breakout; confirm module level shifter / pull-ups are ESP32-S3 compatible.
- DS1307 SDA → GPIO 12, SCL → GPIO 13.
- Common GND between ESP32 and DS1307.
- If module includes onboard 3V coin cell, remove DS3231 coin cell or move battery to DS1307 module only.

## Test & Validation

### Unit / Native
- Add `test_rtc_manager.cpp` cases:
  - DS1307 detected trusted path.
  - Power-loss → untrusted until `adjustTime` or NTP/backend sync.
  - `getTime()` returns trusted DS1307 first, then system, then invalid.
  - `isNightMode()` invalid returns false.
- Update existing fake clock tests if they assert DS3231 strings.
- Update `native` build filter / lib dependencies if needed.

### Integration / Hardware
- Flash gateway with migrated pins and DS1307 module.
- Verify `Wire.begin(12,13)` scan finds `0x68`.
- Verify boot logs:
  - DS1307 detected
  - First NTP sync updates RTC if needed
  - Scheduler runs 1-second group phases
- Disconnect Wi-Fi after time sync and confirm scheduler keeps correct time from DS1307 for at least several minutes/hours.
- Simulate invalid RTC by power-removing coin cell and confirm fail-safe OFF.
- Backend time push flow: receive ack and new `time_source`.

## Rollback
- Keep old branch/tag with DS3231 code as rollback path.
- Hardware rollback requires rewiring to 21/22 and swapping module.

## Out of Scope
- Node-side RTC migration for ATmega8.
- Multi-RTC arbitration.
- GPS time source.
